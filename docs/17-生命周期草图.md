## 图 A 进程骨架

```
                     ┌───────────────────────────────┐
   HTTP / SSE  ──────►│ 进程 A：APIServer (uvicorn)    │
                     │  ① API 层                      │
                     │  ② AsyncLLM（引擎门面，同进程） │
                     └───────────┬───────────────────┘
                                 │ zmq ROUTER → DEALER（请求）
                                 │ zmq PUSH → PULL（结果）
                     ┌───────────┴───────────────────┐
                     │ 进程 B：EngineCore            │
                     │  ③ 收件/排队   ④ Scheduler     │
                     │  ⑤ Model Runner ⑥ 回流出口     │
                     │  ★ 主线程跑 run_busy_loop ★    │
                     └───────────────────────────────┘
```

单卡 uniproc 无独立 Worker 进程 —— Worker / Model Runner 都长在 EngineCore 进程里。

## 图 B 七站（线性 + 一个循环）

```
① API 层            POST /v1/chat/completions → 路由 → OpenAIServingChat
                    　　└─ engine_client.generate(prompt, sampling_params)
        │
        ▼
② AsyncLLM          generate → add_request
   （进程 A）          ├ InputProcessor.process_inputs ← ★「文本」变「token id」在这
                     │    └ renderer 渲 chat 模板 + tokenize + 多模态预处理
                     ├ output_processor.add_request（登记「这个请求要回流」）
                     └ engine_core.add_request_async → zmq ROUTER ──┐
        │                                                          │ IPC
        ▼                                                          ▼
③ 收件/排队         process_input_sockets（zmq DEALER）→ input_queue
   （进程 B）          run_busy_loop → _process_input_queue
                     → _handle_client_request(ADD) → preprocess_add_request
                     → scheduler.add_request → 落进 waiting
        │
        ▼
④ Scheduler         schedule()：waiting → running（chunked prefill 按 token 预算切）
   ★ 循环体第一站     ◄── ★ KV 分配站：get_computed_blocks（前缀命中，白拿 KV）
                         + allocate_slots（要不到 block → 抢占 preempted / 回 waiting）
                     → SchedulerOutput（scheduled_new_reqs + 每 req 的 num_scheduled_tokens）
        │
        ▼
⑤ Model Runner      executor.execute_model(scheduler_output) → Worker → GPUModelRunner
   ★ 循环体第二站       _prepare_inputs：block_table / slot_mapping / query_start_loc
                     → 逐层跑模型，Attention Backend（flash / triton / linear / mamba…）
                     → logits → Sampler（惩罚 → logit bias → temperature → min_p/topK/topP
                       → 采样）→ token_id
        │
        ▼
⑥ 回流              scheduler.update_from_output(scheduler_output, model_output)
   ★ 循环体第三站       → EngineCoreOutputs → output_queue
                     → process_output_sockets（zmq PUSH）──► 回到进程 A
        │
        ▼
⑦ 出站              output_handler 取回 EngineCoreOutputs（zmq PULL）
   （进程 A）          → output_processor.process_outputs（增量 detokenize → 文本）
                     → RequestOutput → asyncio.Queue → SSE chunk
                     → 未 finished：回 ④ 再来一圈（每圈 = 1 个 decode token）
```

**循环怎么读**：③ 只进一次（新请求）；④⑤⑥ 每圈出 1 token；⑦ 每圈吐一段 SSE。
39 token 回答 ≈ **1 圈 prefill + 38～39 圈 decode**（spec decode 一圈多 token，圈数会少）。

两个细节：

- 无请求时 `step()` 首行返回（`scheduler.has_requests()` 假）→ 不跑 GPU，只睡 1ms。
- 开 async scheduling 时，一圈里 `execute_model` 与 `sample_tokens` 是两次调用（先 logits 后采样），盒 ⑤ 仍是一个盒。

## 站台表

| 站              | 干什么                                 | 关键符号                                                                            | 进程 · 线程               | 循环体里？           |
| --------------- | -------------------------------------- | ----------------------------------------------------------------------------------- | -------------------------- | -------------------- |
| ① API          | 收 HTTP、解析、SSE 回包                | `OpenAIServingChat.create_chat_completion`                                        | A · uvicorn event loop    | 否                   |
| ② AsyncLLM     | 文本→token id；登记请求；结果翻回文本 | `InputProcessor.process_inputs`、`OutputProcessor`                              | A · event loop            | 否（伴随循环）       |
| ③ 收件         | 收 zmq 消息、排队、分发                | `process_input_sockets`、`_process_input_queue`、`_handle_client_request`     | B · 主线程 + 2 IO 线程    | 否                   |
| ④ Scheduler    | 选 batch、分 KV、算本次跑多少 token    | `Scheduler.schedule`、`KVCacheManager.get_computed_blocks` / `allocate_slots` | B · 主线程                | **是**         |
| ⑤ Model Runner | 组 batch、跑模型、采样出 token_id      | `GPUModelRunner.execute_model`、`_prepare_inputs`、`Sampler.forward`          | B · 主线程（GPU）         | **是**         |
| ⑥ 回流         | token 打回前端                         | `Scheduler.update_from_output`、`process_output_sockets`                        | B · 主线程 + 输出 IO 线程 | **是**         |
| ⑦ 出站         | detokenize、SSE                        | `AsyncLLM._run_output_handler`、`OutputProcessor.process_outputs`               | A · event loop            | **是**（每圈） |

## docs/13 那三问的答案

1. **文本→token id 在哪站？**
   → ② AsyncLLM 的 `InputProcessor.process_inputs`（调 `renderers/` 渲模板再 tokenize）。不在 EngineCore、不在 Model Runner —— EngineCore 收到的已是 token id 数组。
2. **回流从哪站起？**
   → ⑤ Sampler 出 `token_id`（GPU 上）→ ⑥ `update_from_output` 打包 `EngineCoreOutputs` → zmq PUSH 出 EngineCore → ⑦ `process_outputs` 增量 detokenize → SSE。**跨进程那刻在 ⑥ 末尾**。
3. **39 token 转几圈？**
   → 约 39 圈（首圈 prefill 吃完整 prompt，之后每圈 1 token）。chunked prefill 切长 prompt、开 spec decode → 偏离。

## V0 vs V1（只记这些）

- 抢占：V0 有 swap（KV 挪 CPU），V1 只有 recompute。
- 引擎类：`LLMEngine` / `AsyncLLMEngine` 现在是 `v1` 的 7 行别名。V0 引擎类已删。
- detokenize：V0 整句回解，V1 增量。
