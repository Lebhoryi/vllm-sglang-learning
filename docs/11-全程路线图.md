## 一、方法论：三层漏斗（这是全篇最重要的一节）

你 09-30 的困惑「先粗看流程，还是直接按模块解锁」，本质是**跳层**。正确顺序：

```
L1 系统层 ── 一次请求从 HTTP 进到 token 出，经过哪几站
   │         产出：一张链路图 + 每站传的对象名
   │         验收：能对着图讲 5 分钟
   ↓
L2 模块层 ── 每个模块「管什么状态、输入从哪来、输出给谁、日志哪行是它」
   │         产出：6 行 × 4 列的模块表
   │         验收：看到任意一条日志行，能说出是哪个模块打的
   ↓
L3 函数层 ── 关键函数逐段精读（调度决策、block 分配、tensor 准备…）
             产出：手写伪代码 + 状态变化图
             验收：能自己算出日志里的数字 / 能预测改参数后的行为
```

### 三条铁律

1. **不许跳层**。L1 没闭环就别进 L2；L2 没填满就别钻 L3。跳层的症状是「每个字都认识，连起来不知道在干嘛」。
2. **L2 不读实现**。只读文件头 docstring + 类/方法签名（`grep "^class \|^    def "`）。读实现 = 掉进 L3 陷阱。
3. **每层必须有「可交付物」**。读完不算完成，产出物才算。图 / 表 / 伪代码，三选一。

## 五、三个风险与对策

| 风险 | 症状 | 对策 |
|---|---|---|
| **时间充裕 → 拖延** | "反正还有三个月" | 每周必须有可交付物。没产出 = 这周不算过 |
| **只读不写** | 读的时候都懂，合上就忘 | 强制产出物：伪代码 / 图 / 表。**输出才能固化** |
| **迷失细节**（L3 陷阱） | 在某个分支里钻了半天，忘了它属于哪 | 每钻 30 分钟，抬头问一次"我在 L1/L2/L3 哪一层？" |

> 原计划"卡 9/30 到期"的压力已解除，但**三个月最容易的失败方式不是没时间，是没有检查点**。上面 13 个里程碑就是检查点。
