## 关键发现（2026-09-08 源码核查）

1. **vLLM 的 V4 模型实现是双后端**：`vllm/models/deepseek_v4/{nvidia/model.py, xpu/model.py, xpu_sparse.py, dspark.py}`。
   **xpu/ 即昇腾实现（vllm-ascend 同源）→ 自研栈适配 V4 的直接参考模板**，阶段三重点读。
2. vLLM 还躺着 2026 前沿模型目录：`deepseek_v32/`、`hy_v4/`、`qwen4_exp/`、`glm5next/`、`dots3_note/`、`kimi_k3/`、`minimax_m3/` —— 与岗位目标模型（V4/Qwen3.8/GLM-5.3）对得上，后续静态读实现的好素材。
3. SGLang 侧 V4 支持更"满配"：模型 ×3（本体/nextn/dspark）、专用 KV 池、hybrid cache、HIP 后端——它的 V4 工程完整度是当前参考标杆。

## 附录：vLLM 侧 V4 实现结构（2026-09-08 源码实测，阶段三前可泛读）

`vllm/models/deepseek_v4/` 布局：`attention.py`、`compressor.py`（压缩态 KV）、`sparse_mla.py`、`quant_config.py`、`common/`、`nvidia/`、`amd/`、`xpu/`。

**类骨架（nvidia/model.py）**：

```
DeepseekV4MLP（:101）
  → DeepseekV4MegaMoEExperts（:180，deep_gemm MegaMoE：FP8/FP4、
     shared-expert 融合、SM100 才开部分路径）
  → DeepseekV4MoE（:749）
  → DeepseekV4DecoderLayer（:1096）
  → DeepseekV4Model（:1273，EagleModelMixin → 支持投机）
  → DeepseekV4MixtureOfExperts（:1713，MixtureOfExperts 子类 → EP）
  → DeepseekV4ForCausalLM（:1750）
```

**注意力（attention.py + nvidia/）**：

- `DeepseekV4Attention`（:128，ABC）：`forward_mqa` 平台稀疏 MLA 前向；`q_lora_rank` + `q_norm`（MLA 低秩 q 投影）；RoPE 在 indexer/compressor **之前**；`window_size` ← `config.sliding_window`（SWA 窗口）；indexer 仅在 **C4A 稀疏注意力**层挂载（`SparseAttnIndexer`）；`fused_indexer_q_rope_quant` 带 **MXFP4_BLOCK_SIZE**（FP4 indexer cache 的出处）
- 后端三件套（nvidia/）：
  - `flashinfer_sparse.py` → `DeepseekV4FlashInferMLASparseBackend`（:98，DSv4 稀疏 metadata/cache 布局、SM120 topk 稀疏、kernel block size 约束）
  - `flashmla.py` → `DeepseekV4FlashMLAAttention`
  - `flashinfer_sparse.py` 内另有 `DeepseekV4FlashInferSM120Attention`（Blackwell 专用）
- 稀疏缓存：`vllm/v1/attention/backends/mla/sparse_swa.py` → `DeepseekV4SWACache`（+ 上一轮记过的 `flashattn_mla_sparse`、`flashinfer_mla_sparse{,_sm90,_sm120}`）
- indexer：`vllm/model_executor/layers/sparse_attn_indexer.py` + `v1/attention/backends/mla/indexer.py`（`dsa_indexer_uses_fp4`）

## 附录 2：SGLang 侧 V4 结构（预核实，2026-09-08；阶段三细读）

`srt/models/deepseek_v4.py` 类骨架（精确到行号）：

```
MhcOps（:180，MHC=Multi-Head Compression 相关命名元组）
  → MqaAttentionBase（:626，MQA 化注意力基类）
  → MQALayer（:870）
  → DeepseekV4DecoderLayer（:1883）
  → DeepseekV4Model（:2801）
  → DeepseekV4ForCausalLM（:3164）
```

注意力配套（`srt/layers/attention/dsv4/` + `sglang/kernels/ops/attention/dsv4/`）：

- `Compressor`（压缩态 KV——对应 vLLM 的 `compressor.py`）
- `C4Indexer`（C4A 稀疏 indexer——对应 vLLM 的 `SparseAttnIndexer`）
- `per_token_group_quant_fp8_dsv4_wo_a`（FP8 量化 o_proj 路径）
- NPU 专用：`srt/hardware_backend/npu/dsv4/`（昇腾路径，同 vLLM 的 xpu/）
- DSA 分支：bf16-KV 路径 + prefill-CP all-gather（:1057/:1092 注释）

**双引擎对应关系（Docs/04 映射表 SGLang 列的预填）**：

| V4 概念 | vLLM | SGLang |
|---|---|---|
| 稀疏 indexer | `SparseAttnIndexer` + **FP4** indexer cache（MXFP4_BLOCK_SIZE） | `C4Indexer` + **FP8** dsv4 量化路径 |
| 压缩态 KV | `compressor.py` | `Compressor` |
| 平台路径 | `xpu/`（昇腾） | `hardware_backend/npu/dsv4/`（昇腾） |
| DSA 稀疏解码 | `flashinfer_sparse.py` 等三后端 | `dsa/` + `dsv4/` kernels |

> **Lyngor 视角**：同一概念（稀疏 indexer 的量化位点）双引擎选型不同——vLLM FP4 vs SGLang FP8。**自研栈做 V4 适配时这是必须拍板的点**，阶段三读实现时对比两家的取舍理由。
