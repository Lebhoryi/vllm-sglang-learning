**今天的产出**：一页"请求的一生"时间线（`QUEUED` → `SCHEDULED` → `NEW_TOKENS` → … → 结束 / `PREEMPTED` 回队列）。

| 1 | `design/metrics.md` | 45 min | 只读 `Metrics Collection` / `Scheduler Stats` / `Engine Core Events` 三节。**EngineCore = 内循环（性能关键）、AsyncLLM = 外循环（承担开销）**这个分工是全篇最值钱的一句 |

## 四条纪律（比读什么更重要）

1. **只读讲结构、讲权衡的页。** 凡是"怎么配参数 / 怎么部署 / 支持哪些格式"的页整块跳过：量化工具链（awq/gptq/bnb/gguf/torchao…）、各种连接器、多模态、K8s / Docker / Nginx、tool calling、structured outputs、speculative decoding 全家族。省下的时间比多读 100 页值。
2. **页首先看有没有 warning。** 出现"historical document"、"written based on commit …"、"Current State (v0)" 或具体年份 → 立刻降级为"只读概念，不读实现"。
3. **代码锚点一律回本地。** 官方在线页里的类名、文件路径、行号可能已过时（它们的 `latest` 比你的源码新一个 minor；`stable` = v0.31.0，你的源码 = 09-24）。你本地那份 `docs/` 快照才是和你代码对齐的官方文档。
4. **每天必须有产出。** 图 / 时间线 / 表格，三选一。四天结束的产出是 4 页 + 1 张总图；没有产出就等于没读。
