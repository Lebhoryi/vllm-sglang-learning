## 两套日志怎么配合走读（建议顺序）

1. **先跑/先看 serve 日志**（logs/vllm-qwen35-08b-*.log）：用上表 #1→#16 顺序过一遍，重点抓"双进程前缀"（#2/#4）和"路由注册表"（#1）—— 这是 docs/01 Q1 的日志侧答案；
2. **再看离线日志**（test_vllms/test_qwen3.5_0.8b.log）：内核环节（#7 chunked prefill 8192、#12 KV 数字、#13 显存账）更干净，对照 serve 版差异；
3. **动手验证**（可选，09/14 前）：
   ```bash
   # serve 链路（logs/ 收日志）
   MODEL_PATH=/data/hf_models/Qwen3.5-0.8B ./scripts/start_vllm_qwen35_08b.sh
   ./scripts/test_chat.sh 8001 /data/hf_models/Qwen3.5-0.8B "再走一遍链路"
   # 离线内核（test_vllms 冻结目录只读，新日志进 logs/）
   MODEL_PATH=/data/hf_models/Qwen3.5-0.8B python test_vllms/test_vllm_qwen3.5_0.8b.py 2>&1 | tee logs/offline-08b-$(date +%m%d).log
   ```

## 走读时的 3 个观察点（对检查点①有用）

1. **Q1 的"每跳传什么"**：日志看不到对象，但"进程前缀切换"（APIServer → EngineCore）就是 core_client 的通信边界 —— 传的是 `EngineCoreRequest`（input_processor 加工后）。
2. **Q4 的 KV layout**：#11 的 544/784 就是 `kv_cache_layout.py` 在算的"页对齐"结果 —— 混合注意力模型专属行为。
3. **Q3 的 preemption**：当前日志里 `Running: 0 reqs`（冒烟无压力），preemption 要逼出来 —— W2 27B 限参后跑高并发能看到（v0.28 主路径是 recompute，v1 无 CPU swap）。
