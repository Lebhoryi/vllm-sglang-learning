## Step 4：27B + benchmark（W2）

```bash
# D7：下载（hf-mirror，54GB，建议后台；若已存在跳过）
export HF_ENDPOINT=https://hf-mirror.com
huggingface-cli download Qwen/Qwen3.8-27B --local-dir <model_dir>/Qwen3.8-27B

# D8：起服务（27B 必须限参，A100-80G 单卡）
MODEL_PATH=<model_dir>/Qwen3.8-27B PORT=8002 \
  vllm serve <model_dir>/Qwen3.8-27B --host 0.0.0.0 --port 8002 \
  --max-model-len 16384 --max-num-seqs 16 --gpu-memory-utilization 0.9 \
  --dtype bfloat16 2>&1 | tee -a logs/vllm-qwen38-27b.log

# D9-D10：benchmark（v0.28 新 CLI！旧 python -m vllm.benchmarks.benchmark_serving 已废弃）
# --dataset-name random = 免外部文件；input/output 长度可调
vllm bench serve \
  --model <model_dir>/Qwen3.8-27B \
  --port 8002 \
  --dataset-name random \
  --num-prompts 200 \
  --random-input-len 512 \
  --random-output-len 128 \
  --max-concurrency 16 \
  --request-rate inf \
  --save-result --result-dir logs 2>&1 | tee logs/bench-27b-vllm-$(date +%m%d).log
```

参数速查（在本机源码 `vllm/benchmarks/serve.py` + `vllm/benchmarks/datasets/datasets.py` 实测）：

- `--dataset-name` 默认 `random`；可选 sharegpt/sonnet/hf/custom 等
- random 默认 `--random-input-len 1024`（此处压到 512 更贴近 27B 限参后场景）、`--random-output-len 128`
- `--num-prompts` 默认 1000（此处 200 先小规模）
- `--request-rate inf` = 打满；`--max-concurrency` = 并发上限
- 更多：`vllm bench serve --help`

**W2 要拿到的数字**：TTFT（平均/p50/p99）、TPOT、输出吞吐（tokens/s）、请求吞吐（req/s）、错误率。`--save-result` 的 json 一并保留在 logs/，解读写进笔记。

## 常见坑速查

| 坑 | 处理 |
|---|---|
| 端口被占 | 换端口：`PORT=` 环境变量（脚本支持） |
| huggingface.co 超时 | 一律 `HF_ENDPOINT=https://hf-mirror.com` |
| 显存不够（被人占用） | `--gpu-memory-utilization` 降到 0.7，或 `--max-model-len` 降 8192 |
| 27B OOM | 确认 `--max-num-seqs 16 --max-model-len 16384` 生效；再不行换 AWQ 版 |
| 起服务报 qwen3_5 不支持 | 不可能：vllm 0.28.0 已注册 Qwen3_5（实测） |
| git 操作超时 | 主力实验机上别对 NFS .git 跑 git；git 操作在本地工作机做 |
| benchmark 命令报错 | 用 `vllm bench serve --help` 看当前版本参数（旧 `python -m vllm.benchmarks.benchmark_serving` 已废弃会直接报错提示） |
